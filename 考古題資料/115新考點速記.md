## 一、Agentic AI／AI Agent（115 最大新主軸）

### 核心能力
- AI Agent 五大能力：**感知（Perception）、規劃（Planning）、工具呼叫（Tool Use）、記憶（Memory）、自主執行**。
- ★陷阱：Agent 的「環境適應能力」＝**泛化能力（Generalization）**；**不包含「發明新技術」**。

### ReAct（Reasoning and Acting）
- 循環：**Thought（推理）→ Action（呼叫工具）→ Observation（觀察結果）→ 再判斷**。
- 適用情境：**探索式、路徑不固定**、需要「自行判斷資訊是否足夠並調整查詢方向」的任務。
- 不適用：流程固定、規則明確（如固定格式 PDF 批次翻譯、依規則判斷退貨）。
- ReAct 屬「以思維鏈（CoT）為基礎發展而來」的提示框架；同類還包含 Tree-of-Thought、Self-consistency。
- ★陷阱：**Zero-shot Learning 不是**由 CoT 衍生。
- 幻覺防治：System Prompt 須明文要求「即時性問題先呼叫 web_search 驗證」，否則 Agent 會依賴既有知識產生幻覺。

### Multi-Agent 協作
- 常見架構：**Orchestrator Agent**（任務分配）＋多個 **Worker Agent**（各自執行）。
- ★容錯關鍵：Orchestrator 具備**結果評估能力**，對不合格結果觸發 **Retry（重試）或重新分配給不同 Worker**，並記錄失敗原因（單一 Worker 失敗不可直接中止整體任務）。
- ★最根本風險：各 Agent 之間**缺乏有效的上下文（Context）同步機制**，導致各自持不一致資訊做決策（不是記憶體不足、不是模型廠牌不同）。

### 真題精選
- **115-1 中級 科目1-015**：Orchestrator 發現 Worker 品質不符預期 → 正解 **(B) 觸發重試／重新分配並記錄失敗原因**。
- **115-1 中級 科目1-016**：ReAct Agent 答即時資料卻直接產出 → 正解 **(A) System Prompt 未要求先以工具驗證，導致幻覺**。
- **115-2 初級 科目2-035**：多代理資訊不同步 → 正解 **(A) 缺乏 Context 同步機制**。
- **115-3 初級 科目2-029**：查詢前先分析需求、取得結果再判斷 → **ReAct**。

## 二、MCP（Model Context Protocol）

### 定位
- MCP ＝ **模型與外部工具／系統互動的標準化通訊協議**；RAG ＝ **補充模型知識來源**（檢索外部知識）。
- ★一句話區分：**MCP 管「手腳」（工具/系統存取），RAG 管「記憶」（知識補充）**。
- MCP **不是**降低訓練成本、**不是**資料檢索技術、**不是**取代資料庫管理系統。

### 角色
- **MCP Server**：提供標準化工具與資料存取能力（查詢訂單、取得產品資訊…），模型透過協定呼叫。
- MCP Server **不等於** LLM 本身，也不負責生成自然語言。
- 後端資料庫**不需**直接連接使用者介面。

### MCP vs Skill
- **MCP**：提供 AI 代理統一存取外部工具與資料來源。
- **Skill**：封裝需要「AI 語意理解與專業判斷」的**可重複使用能力模組**。
- ★兩者**功能不同、不可互相取代**；也都**不需每次重新訓練模型**。

### 「即時最新外部資訊」怎麼選？
| 需求 | 正解技術 |
|---|---|
| 推理時即時存取最新外部文件／API 規範 | **MCP 工具整合** |
| 讓模型「永久記住」新知識、改變語氣風格 | Fine-tuning |
| 大模型壓成小模型 | 知識蒸餾 |
| 重複使用既有提示內容以降延遲 | Prompt Caching |

### 真題精選
- **115-1 初級 科目2-012**：MCP vs RAG → 正解 **(B) MCP 重互動、RAG 重知識來源**。
- **115-2 初級 科目2-020**：生成式助手呼叫到舊版 API → 正解 **(D) 透過 MCP 即時存取最新外部文件**。
- **115-3 初級 科目2-022**：MCP 客服架構 → 正解 **(B) MCP Server 提供標準化工具與資料存取能力**。
- **115-3 初級 科目2-026**：MCP 與 Skill → 正解 **(B) MCP 管外部存取、Skill 封裝語意能力**。

## 三、Solution Graph（解決方案圖）

### 定義
- 一種把**問題解決步驟表示為節點與連結的有向無環圖（DAG）**，讓 AI 能逐步推理解決問題。
- 作用：**定義代理可參考的任務分解與決策路徑結構**（不是取代 LLM 推理、不是知識庫、不是強化學習模型）。
- LLM 與 Solution Graph：**LLM 依問題推理、產生任務步驟與關聯，並據此協助建構 Solution Graph**。

### Solution Graph vs Knowledge Graph（★必考比較）
| 面向 | Solution Graph 解決方案圖 | Knowledge Graph 知識圖 |
|---|---|---|
| 生命週期 | **單次任務**、用後即棄 | **長期保存**、跨任務共用 |
| 內容 | 本次任務的子任務安排與**依賴關係** | 結構化的**實體與關係知識** |
| 用途 | 任務規劃、行動依據 | 各項任務查詢知識 |

### 為何先建 Solution Graph（優點）
- 引導 AI **分階段規劃與執行、逐步驗證各階段結果**，降低推理缺乏依據、遺漏上下文或**幻覺**的風險。
- ★陷阱：Solution Graph **不會自動糾正錯誤**、**不能完全避免虛構**、**不是預先定義所有答案**。

### 真題精選
- **115-1 初級 科目2-016**：Solution Graph 主要功能 → 正解 **(D) 定義任務分解與決策路徑結構**。
- **115-2 初級 科目2-040**：→ 正解 **(D) 有向無環圖，使 AI 逐步推理解決問題**。
- **115-2 初級 科目2-041**：LLM 與 Solution Graph → 正解 **(A) LLM 推理產生步驟並協助建構圖**。
- **115-3 初級 科目2-010 / -011**：vs Knowledge Graph（單次任務 vs 長期共用）、分階段降幻覺。

## 五、Vibe Coding 與 AI 輔助開發

### 五種開發方式辨識（★配對題）
| 方式 | 特徵 |
|---|---|
| **Prompt Engineering** | 工程師分析需求、設計與優化提示詞，讓 AI 穩定產出程式片段，**自行整合與測試** |
| **Vibe Coding** | 以**自然語言**描述功能，AI 生成／修改程式碼，**多輪對話迭代**逐步完成 Prototype |
| **Low-Code** | 透過**預設元件組合**快速建構，彈性受限於平台功能範疇 |
| **No-Code** | 無需程式碼，視覺化拖拉 |
| **Agentic Coding** | 由 Agent 自主規劃並完成多步開發任務 |

### Vibe Coding 重點
- 本質：**自然語言驅動 AI 生成客製化程式碼**，彈性高但**產出品質高度依賴提示詞精準度**。
- 適合：**快速原型（MVP）**；不適合直接上正式環境。
- 風險與治理：**程式碼品質與安全風險** → 正解措施為**納入審查、重構與安全測試流程**（不是「一直優化提示詞」、不是「沿用 AI 生成碼」）。
- 非技術人員（如行銷）最佳實務：**透過自然語言與 AI 反覆互動，逐步調整需求並驗證產出**。

### 真題精選
- **115-1 初級 科目2-019**：→ 正解 **(C) 納入審查、重構與安全測試**。
- **115-2 初級 科目2-013**：Vibe Coding vs Low-Code → 正解 **(D)**。
- **115-3 初級 科目2-012**：甲乙丙配對 → 正解 **(B) 甲=Prompt Engineering、乙=Vibe Coding、丙=Low-Code**。

## 六、資料洩漏（Data Leakage）與前處理順序 ★高頻陷阱

### 鐵則：**先切分（train/test），再只用訓練集 fit 任何轉換**
| 步驟 | 正確作法 |
|---|---|
| 標準化／正規化 | **先分割**，**僅以訓練集**計算統計量，再套用到測試集 |
| 特徵篩選 | **不可在含測試集的全體資料上**計算相關性／選特徵 |
| 過採樣 SMOTE | **必須在切分後、且只對訓練集**執行 |
| 降維（如 LDA/PCA） | 須**納入交叉驗證流程中一併進行**，不可先用全體資料降維 |

### 常見錯誤（皆為陷阱選項）
- 分割前對全體資料算統計量做標準化 → 資料洩漏。
- 在全體資料（含測試集）上做特徵篩選 → **資料洩漏**，且線性相關無法捕捉非線性關係。
- 先 SMOTE 再切分 → 合成樣本資訊洩漏至測試集 → 指標虛高不可信。
- 先對全體資料 LDA 降維再交叉驗證 KNN → 資料洩漏。

### 真題精選
- **115-1 初級 科目1-006**：標準化順序 → 正解 **(C) 先分割、只用訓練集算統計量再套用測試集**。
- **115-1 中級 科目2-010**：全體資料上做特徵篩選 → 正解 **(B) 造成資料洩漏**。
- **115-1 中級 科目3-044**：先全體 LDA 再 CV → 正解 **(B) 資料洩漏，LDA 應納入 CV 流程**。
- **115-3 初級 科目1-017**：每秒→每小時彙整，資料外洩為**干擾選項**（正解為失去短時變化資訊）。

## 七、類別失衡處理（SMOTE）

- **SMOTE**（Synthetic Minority Over-sampling Technique）：**依少數類樣本的特徵空間，合成產生新的少數類樣本**（不是刪多數類、不是調 loss 權重、不是重新分割）。
- 對照：**class_weight**＝調整損失函數權重；**Random Under-sampling**＝隨機刪多數類。
- ★陷阱：SMOTE **必須只對訓練集**操作，否則造成資料洩漏（見上節）。
- 評估指標：1.6% 這種極度不平衡下，**AUC-ROC 可能過度樂觀，宜改用 PR-AUC**。
- 真題：
  - **115-1 初級 科目1-005**：SMOTE 功能 → 正解 **(B) 依少數類特徵空間合成新樣本**。
  - **115-1 中級 科目1-037**：良品 99%／瑕疵 1% → 正解 **(A) SMOTE 過採樣**。
  - **115-1 中級 科目2-032**：先 SMOTE 再切分 → 正解 **(B) 資訊洩漏、AUC 虛高**。

## 八、AI 生成內容的出處證明

| 技術/機制 | 說明 |
|---|---|
| **SynthID** | Google DeepMind 的**不可見數位浮水印**，嵌入生成內容（如 Gemini／Veo 影片的每一幀） |
| **C2PA（Content Credentials）** | 內容來源與編輯歷程的**元數據**標準，如 Sora 內嵌 |
| **Sora 出處證明** | C2PA 元數據、預設可見動態浮水印、內部反向影像/音訊搜尋工具（★**不包含**「對外開放的實時來源驗證介面」） |

- 真題：
  - **115-1 初級 科目2-006**：Sora 出處證明**不包含** → 正解 **(D) 對外開放的實時來源驗證介面**。
  - **115-1 初級 科目2-022**：Veo 影片嵌入不可見浮水印 → **SynthID**。

## 九、AI 安全防護（Guardrails／越獄／幻覺）

| 名詞 | 定義 |
|---|---|
| **Guardrails 護欄** | 於模型**前後端**部署獨立安全防護網，即時攔截／過濾有害輸入，產生不當內容時阻斷或拒答 |
| **Prompt Injection 提示注入** | 透過外部內容夾帶指令，操控模型偏離任務 |
| **Jailbreak 越獄** | **僅靠對話**（追問、情境設計、誘導）逐步使模型偏離原設定（★未使用外部文件） |
| **Data Leakage 資料外洩** | 洩漏訓練/系統內部資料 |
| **Hallucination 幻覺** | 模型自信地編造錯誤資訊 |

- ★提示鏈（Prompt Chaining）穩定性下降 → 正解是**各中間步驟輸出的驗證機制與護欄（Guardrails）設計**（不是調低 temperature、不是 RAG reindex）。
- ★開源模型上線 → 正解**前後端部署 Guardrails**（不是「信任原廠安全對齊」、不是「全面關鍵字阻擋」、不是「每筆人工審核」）。
- 真題：
  - **115-3 初級 科目2-007**：Prompt Chaining 中間步驟偏差 → 正解 **(A) 中間步驟驗證與 Guardrails**。
  - **115-3 初級 科目2-039**：開源模型安全 → 正解 **(D) 前後端 Guardrails**。
  - **115-3 初級 科目2-043**：僅靠對話誘導偏離 → 正解 **(D) 越獄（Jailbreak）**。

## 速記總表（考前 10 分鐘）

- **MCP**：手腳（工具/系統互動）。**RAG**：記憶（知識補充）。**Skill**：語意能力模組。
- **Solution Graph**：單次任務 DAG。**Knowledge Graph**：長期共用知識。
- **ReAct**：Thought→Action→Observation，適合探索式任務；**Zero-shot 非 CoT 衍生**。
- **Multi-Agent**：Orchestrator 重試／重分配；痛點是 Context 不同步。
- **前處理鐵則**：先切分 → 只用訓練集 fit → SMOTE 只碰訓練集。
- **SMOTE**：合成少數類樣本（非刪多數、非調權重）。
- **Vibe Coding**：自然語言→AI 生成碼→多輪迭代；上線前必經審查／重構／安全測試。
- **出處證明**：SynthID（不可見浮水印）、C2PA（元數據）。
- **Guardrails**：前後端獨立防護網。**Jailbreak**：純對話誘導。**Injection**：夾帶外部指令。
